# 2026-10-04

- 修复 NbaMapWidget 点击 LOGO 播放动画在三星手机无限循环的问题。
- 根因：movie_layout_* 布局中的 ViewFlipper（autoStart=true, flipInterval=20）在 RemoteViews 中会一直循环，没有"播一轮即停"的属性；华为机型是因为到点的每分钟自动更新(changeSimpleLayout)把布局换回去才"看起来只播一次"，三星的定时更新被延迟导致没人切回。
- 修复：在 onReceive 的 LOGO_CLICK 分支，changeMovieLayout 后用 Handler(Looper.getMainLooper()).postDelayed(playTime) 调 changeSimpleLayout 切回静态布局（与 doInEveryMin / ScoreBoardWidget 的既有做法一致）。
- 文件：app/src/main/java/com/nntk/nba/widgets/NbaMapWidget.java

- 同步修复 ScoreBoardWidget：两处动画展示原写死 postDelayed 1800ms 切回，但 espn_anim_layout_* 的帧数各队不同（espnAnimSize 字段 × flipInterval=20ms，如 76人 57帧≈1140ms、湖人 92帧≈1840ms），帧少的队会在窗口内循环 1.5+ 轮。
- 改动：TeamEntity 新增 espnAnimSize 字段；ScoreBoardWidget.teamEntityList() 解析该字段；新增 getEspnAnimPlayTime()（帧数×20+50ms）；doInEveryMin 与 changeGameAnimLayout 的 1800ms 改为按帧数计算（点击路径取 min/hour 两队动画时长的较大值）。
- 文件：ScoreBoardWidget.java、entity/TeamEntity.java

- NbaMapWidget 二次修复（postDelayed 方案在三星无效）：根因是三星 One UI 缓存进程冻结(Cached App Freezer)在广播处理完几秒内冻结进程，Handler.postDelayed 的切回消息不执行。改为 AlarmManager setExact(RTC_WAKEUP) 定时广播 ACTION_STOP_MOVIE 切回静态布局（requestCode=appId, FLAG_UPDATE_CURRENT），点击路径和 doInEveryMin 都改用该机制。
- 附带修复：getPlayTime 的 Optional.get() 改 orElse 兜底（防崩溃导致切不回）；logo.json 中 frameSize 存的是"最后一帧序号"而非帧数（全部差 1，实测 60 处），计算时长改为 (frameSize+1)*interval。
- 本机编译注意：默认 JDK 25 会让 Gradle 8.7 报错 "What went wrong: 25.0.4"，需 JAVA_HOME 指向 JDK 17（/usr/libexec/java_home -v 17.0.9）。
- 文件：NbaMapWidget.java
